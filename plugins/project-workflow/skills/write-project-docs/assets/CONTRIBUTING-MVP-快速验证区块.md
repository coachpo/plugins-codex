### MVP 快速验证

本阶段以验证 [`{{PRODUCT_DOC}}`]({{PRODUCT_DOC}}) 中已确认的核心假设、范围、非目标以及可观察的验收与退出条件为目标，优先实现能够产生有效证据的最小可观察闭环。“最短”是获得可信反馈的路径最短，不是代码、步骤或测试最少。

多个方案均满足 [`STATUS.md`](STATUS.md) 的允许变更与兼容政策、[`{{ARCHITECTURE_DOC}}`]({{ARCHITECTURE_DOC}}) 的架构与安全边界及 [`{{DEVELOPMENT_RULES_DOC}}`]({{DEVELOPMENT_RULES_DOC}}) 的项目规则时，优先选择改动范围小、新增依赖少、容易观察和撤销的方案。对不实质改变上述约束，且局部、低风险、可逆的实现细节，可在既有权限和开发工作流内直接决定；设计类选择遵循“通用设计原则”，实现类选择遵循本节优先顺序。

只实现当前验证所必需的能力，不为未验证需求增加通用化能力、抽象或依赖。不得以 MVP 为由跳过必要验证、降低安全、隐私或数据完整性要求、扩大权限，或把未经验收和必要加固的验证性实现表述为正式架构或生产能力。

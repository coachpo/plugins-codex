# write-project-docs

建立简洁、以仓库事实为依据的简体中文文档集合。八个规范文档及允许的中英文路径是共享约定，不为单个项目增加特例或按项目名分支。

| 路径 | 唯一权威范围 |
| --- | --- |
| `README.md` | 项目入口、安装、普通启动、派生状态摘要和链接。 |
| `STATUS.md` | 生命周期、部署、用户、数据、兼容政策及允许和禁止的变更。 |
| `CONTRIBUTING.md` | 开发环境、开发启动、测试、检查、构建、开发工作流、共享设计与实现原则和完成定义。 |
| `docs/README.md` | 文档索引和权威映射。 |
| `docs/产品说明.md` 或 `docs/product.md` | 产品问题、用户、目标、范围、流程、需求和验收事实。 |
| `docs/架构说明.md` 或 `docs/architecture.md` | 当前架构、责任组件、边界、依赖方向、风险和具体例外。 |
| `docs/开发规范.md` 或 `docs/development-rules.md` | 项目特有代码风格、评审要求和技术实现规则；链接 `CONTRIBUTING.md` 共享规则与规模策略。 |
| `docs/源代码规模与职责规则.md` 或 `docs/source-code-size-and-responsibility-rules.md` | 捆绑模板渲染的、物理独立且与项目技术无关的规模与职责策略。 |

项目根 `AGENTS.md` 是代理专属行为和文档导航界面，不是第九个规范文档。每项事实或政策只保留一个权威来源，其他位置只链接；`README.md` 的状态内容必须是派生摘要并标明以 `STATUS.md` 为准。

## 模式与边界

- 审查、解释、诊断或报告请求只读取、验证并报告，不创建或修改文件。
- 创建、维护、归并、标准化、修复或迁移请求授权修改受请求影响的项目文档，并运行非破坏性验证。
- 删除、移动、归档、清理旧文件、外部写入或扩大到源代码、配置、CI 及其他指令文件需要明确授权。
- 根 `AGENTS.md` 只有一个写入例外：文件已经存在，是普通非符号链接文件，不是生成或外部维护文件，适用指令允许，并且通过 `scripts/update_agents_navigation.py` 修改托管导航区块和脚本定义的标准路径引用。不得创建 `AGENTS.md` 或 `CLAUDE.md`，不得手工改写根文件其他内容；子目录 `AGENTS.md` 和其他指令文件只检查并报告。
- 识别并原样保留生成或托管区块，不手工重写其他技能或脚本拥有的内容。
- 项目事实只来自用户指令或仓库证据。没有证据表示未知，不表示事实为否；不虚构命令、功能、架构、状态、责任组件、计划、环境、用户或数据。
- 省略无法核实的字段和章节，不在文档中写占位符、“待确认”、开放问题、推测或缺失信息清单。
- 通常不询问未记录的外部环境和数据。只有缺少该事实会使必需的 `STATUS.md` 无法形成实质内容时，才问一个关于当前状态的最小事实问题；不延伸询问人员、审批、KPI 或治理信息。
- 不为显得完整而新增审批、汇报、会议、排期、人员治理、发布治理、提交管理、KPI/SLO 或其他行政内容。除非用户明确要求，不新增运行手册、`SECURITY.md`、`LICENSE`、`CHANGELOG.md`、术语表、测试计划、技术设计文档、`docs/INDEX.md` 或 `docs/通用工程规范.md`。
- 说明性正文使用简体中文；代码标识符、命令、路径、配置键和正式产品名保留原文。

## 工作流程

1. 判断请求是只读还是写入，确定实际项目根目录，并读取当前目录及适用父目录的指令文件。
2. 确定本次请求影响哪些权威文档，只盘点支撑这些文档所需的现有文档、托管边界、路径引用、源代码、配置、CI 和测试；只有完整初始化或迁移才执行全仓盘点。
3. 检查与受影响文档直接相关的清单、配置、主要源代码、测试、CI 和可用命令，建立项目事实。彼此独立的读取可以并行。
4. 把现有内容分类为规范文档内容、仍有价值的专项内容、生成或外部维护内容、重复或过时内容、无法核实内容。只读请求完成必要验证和报告后停止，不进入写入步骤。
5. 写入前按需读取 [项目文档详细规则](references/document-rules.md)：单文档任务读取相关章节，完整初始化或迁移读取全文。
6. 为每类双语权威选择一个路径。两个变体同时存在时，只读比较并列出独有事实；询问保留路径和清理授权，获得决定前只暂停该权威的修改，不删除、不合并、不创建第三份文件。其他独立工作可以继续。
7. 把每项已核实且仍有效的事实或政策映射到一个权威文档，保留不冲突的项目约定；创建缺失文件并对现有文件做最小化更新。必需文件证据不足时先做一次最小补充取证，仍不足则按停止条件处理，不创建空壳或虚构内容。
8. 按“共享资源”渲染规模规则、开发规范链接、`CONTRIBUTING.md` 区块，以及符合条件时的根 `AGENTS.md` 导航区块。
9. 运行 `python3 <skill-dir>/scripts/validate_project_docs.py <project-root>` 和适用的仓库文档检查，修复范围内的普通错误。迁移或清理任务还应运行 `--strict` 诊断；运行只读检查不需要清理授权，实际清理仍受授权边界约束。
10. 检查精确 diff，确认脚本没有修改托管区块或标准路径替换范围之外的内容；越界变化视为验证失败并在授权范围内修正。

## 共享资源

资源路径相对于本技能目录解析。

- `scripts/canonical_paths.py` 解析双语权威路径并渲染资产中声明的 `{{...}}` 变量；发现双语冲突时不调用写入脚本。
- `assets/源代码规模与职责规则.md` 是规模规则文档的完整模板，只替换已声明变量，保持 UTF-8、LF 和一个结尾换行。
- 使用 `scripts/update_development_rules.py` 更新开发规范中的规模规则托管区块，不手工编辑该区块。
- 按 `assets/CONTRIBUTING-通用区块.md` 的唯一可见边界更新 `CONTRIBUTING.md`；边界缺失、重复、顺序错误或位于代码围栏或 HTML block 内时拒绝自动修改，不猜测范围。
- 只有根 `AGENTS.md` 满足写入条件时，才使用 `scripts/update_agents_navigation.py` 更新文档导航区块和标准路径引用；运行后检查精确 diff。
- 不在 `CONTRIBUTING.md` 或开发规范中复制规模阈值，只链接选定的规模规则文档。

## 停止与交付

双语冲突只暂停受影响权威。托管边界不唯一或脚本拒绝时保持目标文件不变并报告原因。普通验证错误在范围内则修复；证据、权限、工具不可用或范围外既有失败使完成条件不可达时，不扩大范围、不声称完成，报告失败检查、受影响路径和最小下一步。

写入任务只有在全部受影响的必需文件具有实质内容或规定区块、普通验证和适用仓库检查通过后结束；迁移或清理任务还要求严格诊断通过，或准确报告尚未授权的清理项。

报告以结果开头，列出创建、更新和保留的文件，保留的专项文档，弃用或清理候选，实际验证及结果，根 `AGENTS.md` 托管区块变更或缺失时运行 `init-deep` 的建议，以及仍引用旧路径的非文档位置和子目录指令文件。省略过程复述和填充内容。

# write-project-docs

建立简洁、以仓库事实为依据的文档集合。八个规范文档及允许的中英文路径是共享约定，不为单个项目增加特例或按项目名分支。

| 路径 | 唯一权威范围 |
| --- | --- |
| `README.md` | 项目入口、安装、普通启动、派生状态摘要和链接。 |
| `STATUS.md` | 生命周期、部署、用户、数据、兼容政策及允许和禁止的变更。 |
| `CONTRIBUTING.md` | 开发环境、开发启动、测试、检查、构建、开发工作流、共享设计与实现原则和完成定义。 |
| `docs/README.md` | 文档索引和权威映射。 |
| `docs/产品说明.md` 或 `docs/product.md` | 产品问题、用户、目标、范围、流程、需求和验收事实。 |
| `docs/架构说明.md` 或 `docs/architecture.md` | 当前架构、责任组件、边界、依赖方向、风险和具体例外。 |
| `docs/开发规范.md` 或 `docs/development-rules.md` | 项目特有代码风格、评审要求和技术实现规则；链接 `CONTRIBUTING.md` 共享规则与规模策略。 |
| `docs/源代码规模与职责规则.md` 或 `docs/source-code-size-and-responsibility-rules.md` | 捆绑模板渲染的、物理独立且与项目技术无关的规模与职责策略。 |

项目根 `AGENTS.md` 是代理专属行为和文档导航界面，不是第九个规范文档。每项事实或政策只保留一个权威来源，其他位置只链接；`README.md` 的状态内容必须是派生摘要并标明以 `STATUS.md` 为准。

## 项目文档语言

整套文档使用同一种语言：简体中文或英文。该语言决定四类双语权威的文件名、全部托管区块正文、说明性正文和所有结构锚点，文件名与正文不得分属两种语言。代码标识符、命令、路径、配置键和正式产品名在两种语言下都保留原文。

语言由仓库现状判定：四类双语权威中已存在的文件全部为中文路径时是简体中文，全部为英文路径时是英文，四类都不存在时默认简体中文。用户明确指定语言时，给写入和验证脚本传 `--language zh|en`；与已存在文档冲突时脚本报错并拒绝写入。

不同权威分属两种语言（如产品用中文路径、架构用英文路径）时语言无法确定：写入脚本拒绝继续，验证脚本报告该冲突并继续执行与语言无关的检查。此时只读比较两种路径下的内容并列出各自独有事实，请用户决定统一到哪一种，获得决定前不修改、删除或创建文件。同一权威同时存在两个变体时不提供语言信号，按工作流程第 6 步的冲突分支处理。

改换已有项目的语言是迁移任务：需要用户明确授权，把四类权威文件、结构锚点、托管区块和引用一并切换。

## 模式与边界

- 审查、解释、诊断或报告请求只读取、验证并报告，不创建或修改文件。
- 创建、维护、归并、标准化、修复或迁移请求授权修改受请求影响的项目文档，并运行非破坏性验证。
- 删除、移动、归档、清理旧文件、外部写入或扩大到源代码、配置、CI 及其他指令文件需要明确授权。
- 根 `AGENTS.md` 只有一个写入例外：文件已经存在，是普通非符号链接文件，不是生成或外部维护文件，适用指令允许，并且通过 `scripts/update_agents_navigation.py` 修改托管导航区块和脚本定义的标准路径引用。不得创建 `AGENTS.md` 或 `CLAUDE.md`，不得手工改写根文件其他内容；子目录 `AGENTS.md` 和其他指令文件只检查并报告。
- 识别并原样保留生成或托管区块，不手工重写其他技能或脚本拥有的内容。
- 项目事实只来自用户指令或仓库证据。没有证据表示未知，不表示事实为否；不虚构命令、功能、架构、状态、责任组件、计划、环境、用户或数据。
- `STATUS.md` 用全文件唯一可见精确行控制 `CONTRIBUTING.md` 的 MVP 区块：中文项目用 `MVP 快速验证模式：启用` 或 `MVP 快速验证模式：未启用`，英文项目用 `MVP Fast Validation Mode: Enabled` 或 `MVP Fast Validation Mode: Disabled`。缺失按未启用组合但不推断项目事实；畸形、重复、冲突或写成另一种语言的状态必须停止且不修改 `CONTRIBUTING.md`。
- 只有用户明确要求或既有显式状态支持，且产品文档或已确认任务中的核心假设、范围、非目标、可观察验收与退出条件已核实时，才写“启用”。已有状态虽为“启用”但这些事实无法核实时，保留状态、不运行贡献指南组合脚本、不修改 `CONTRIBUTING.md`，并报告缺口。组合脚本不替代这项语义核实。
- 省略无法核实的字段和章节，不在文档中写占位符、“待确认”、开放问题、推测或缺失信息清单。
- 通常不询问未记录的外部环境和数据。只有缺少该事实会使必需的 `STATUS.md` 无法形成实质内容时，才问一个关于当前状态的最小事实问题；不延伸询问人员、审批、KPI 或治理信息。
- 不为显得完整而新增审批、汇报、会议、排期、人员治理、发布治理、提交管理、KPI/SLO 或其他行政内容。除非用户明确要求，不新增运行手册、`SECURITY.md`、`LICENSE`、`CHANGELOG.md`、术语表、测试计划、技术设计文档、`docs/INDEX.md` 或 `docs/通用工程规范.md`。

## 工作流程

1. 判断请求是只读还是写入，确定实际项目根目录，并读取当前目录及适用父目录的指令文件。
2. 确定本次请求影响哪些权威文档，只盘点支撑这些文档所需的现有文档、托管边界、路径引用、源代码、配置、CI 和测试；只有完整初始化或迁移才执行全仓盘点。
3. 检查与受影响文档直接相关的清单、配置、主要源代码、测试、CI 和可用命令，建立项目事实。彼此独立的读取可以并行。
4. 把现有内容分类为规范文档内容、仍有价值的专项内容、生成或外部维护内容、重复或过时内容、无法核实内容。只读请求完成必要验证和报告后停止，不进入写入步骤。
5. 写入前按需读取 [项目文档详细规则](references/document-rules.md)：单文档任务读取相关章节，完整初始化或迁移读取全文。
6. 为每类双语权威选择一个路径。同一权威的两个变体同时存在时，只读比较并列出独有事实；询问保留路径和清理授权，获得决定前只暂停该权威的修改，不删除、不合并、不创建第三份文件。其他独立工作可以继续。
7. 把每项已核实且仍有效的事实或政策映射到一个权威文档，保留不冲突的项目约定；按选定语言创建缺失文件并对现有文件做最小化更新，结构锚点用该语言的精确措辞。必需文件证据不足时先做一次最小补充取证，仍不足则按停止条件处理，不创建空壳或虚构内容。
8. 按“共享资源”渲染规模规则和开发规范链接；先按已核实事实更新 `STATUS.md`。状态为“启用”时还须完成上述语义核实，然后才运行 `python3 <skill-dir>/scripts/update_contributing.py <project-root>` 组合 `CONTRIBUTING.md`；未启用或缺失时可直接运行。最后按条件更新根 `AGENTS.md` 导航区块。
9. 运行 `python3 <skill-dir>/scripts/validate_project_docs.py <project-root>` 和适用的仓库文档检查，修复范围内的普通错误。普通验证检查规范文件完整性、MVP 状态、共享资源与组合结果、marker 区块漂移、重复区块和断链；旧路径、嵌套指令引用和疑似重复的规模规则只产生迁移警告。迁移或清理任务还应运行 `--strict` 诊断；运行只读检查不需要清理授权，实际清理仍受授权边界约束。
10. 检查精确 diff，确认脚本没有修改托管区块或标准路径替换范围之外的内容；越界变化视为验证失败并在授权范围内修正。

## 共享资源

资源路径相对于本技能目录解析。每个共享 asset 都有中英两份，分别位于 `assets/zh/` 和 `assets/en/`；脚本按判定出的项目文档语言选择目录，不混用两种语言的 asset。下文用 `assets/<lang>/` 表示这一对。

- `scripts/canonical_paths.py` 判定项目文档语言、解析每类双语权威选定的路径，并渲染资产中声明的 `{{...}}` 变量。
- `assets/<lang>/` 下的规模规则模板是规模规则文档的完整内容，只替换已声明变量，保持 UTF-8、LF 和一个结尾换行。
- 共享区块 asset 由 `<!-- write-project-docs:<名称>:start -->` 与 `<!-- write-project-docs:<名称>:end -->` HTML 边界注释包裹完整正文，写入目标文件时保留这些标记。marker 本身与语言无关，中英 asset 使用同一组 marker。脚本用 marker 定位并完整替换已有区块；marker 缺失、重复、顺序错误或位于代码围栏或 HTML block 内时必须拒绝自动修改，不得猜测范围。
- 使用 `scripts/update_development_rules.py` 更新开发规范中的规模规则托管区块，不手工编辑该区块；已有 `<!-- write-project-docs:development-source-size:start -->` 与 `<!-- write-project-docs:development-source-size:end -->` 边界时完整替换，否则紧跟开发规范 H1 只插入一次。
- `assets/<lang>/` 下的 CONTRIBUTING 基础区块始终作为基础区块；仅在显式启用状态下，由 `scripts/update_contributing.py` 把同目录 MVP 区块插入基础区块的实现原则小节末尾。脚本只机械解析与组合，不核实启用依据；组合结果保留 `<!-- write-project-docs:shared-contributing:start -->` 与 `<!-- write-project-docs:shared-contributing:end -->` 边界，已有边界时完整替换，否则在合适位置只插入一次。
- 只有根 `AGENTS.md` 满足写入条件时，才用选定路径渲染 `assets/<lang>/` 下的导航 asset，并使用 `scripts/update_agents_navigation.py` 更新文档导航区块和标准路径引用；已有 `<!-- write-project-docs:document-navigation:start -->` 与 `<!-- write-project-docs:document-navigation:end -->` 边界时完整替换，否则在合适位置只插入一次；运行后检查精确 diff。
- 不在 `CONTRIBUTING.md` 或开发规范中复制规模规则文档的行数信号和职责自检条款，只链接选定的规模规则文档。行数信号只用于触发审查，不作为拆分判定，别处复述会把它变回硬性上限。

## 停止与交付

语言冲突停止全部写入，验证仍执行并报告与语言无关的检查；同一权威的双变体冲突只暂停该权威。`STATUS.md` 缺失、为符号链接、不是 UTF-8，MVP 状态畸形/重复/冲突/写成另一种语言，托管边界不唯一，或托管区块外已有同名顶层 MVP 标题时，保持 `CONTRIBUTING.md` 不变并报告原因。普通验证错误在范围内则修复；证据、权限、工具不可用或范围外既有失败使完成条件不可达时，不扩大范围、不声称完成，报告失败检查、受影响路径和最小下一步。

写入任务只有在全部受影响的必需文件具有实质内容或规定区块、普通验证和适用仓库检查通过后结束；迁移或清理任务还要求严格诊断通过，或准确报告尚未授权的清理项。

报告以结果开头，列出创建、更新和保留的文件，保留的专项文档，弃用或清理候选，实际验证及结果，根 `AGENTS.md` 托管区块变更或缺失时运行 `write-agent-guides` 的建议，以及仍引用旧路径的非文档位置和子目录指令文件。文档语言不是默认简体中文或本次发生变更时说明该语言。省略过程复述和填充内容。

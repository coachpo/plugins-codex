# Draft Consensus Goal

把当前讨论整理成一个可执行 GOAL 的完整文本。本次调用只授权起草、输出和必要的只读核实；不得查询现有 Goal 状态、调用任何 Goal 创建或状态机制、修改文件或执行草案。

## 确立事实依据

审阅当前可见对话、压缩摘要和其他可用状态。必要时只读检查相关工作区材料，以核实项目事实、路径、命令、约束和完成检查；不得推断压缩状态未保留的细节。

分别处理决定、事实和默认值：

- 用户已接受且未被取代的决定定义目标；明确解决同一问题的较新决定取代较早决定。
- 已核实的工作区事实只用于确认可行性、路径、命令和当前状态，不扩大用户授权。
- 适用的非强制项目约定只在用户没有作出决定时作为默认值。

未被接受的助手建议、备选方案、引用、示例、头脑风暴、沉默和已被取代的决定都不算共识。不得静默拼接不兼容要求，也不得虚构需求、事实、路径、命令、接口、约束、权限、风险或阻塞项。

## 处理不确定性

当假设不会实质改变结果、范围、授权、成本或风险时，可以作出合理假设，并在“约束与授权”字段中以“假设：”明确标记。

若一个未决选择会实质改变上述任一项，只提出解决该选择所需的最小问题，不输出 GOAL。不得因普通实现层面的不确定性而暂停。

## 编写 GOAL

使用简体中文编写完整 GOAL。文件路径、标识符、命令、代码、API 名称、产品名称和引用原文保留准确拼写。

编写前完整读取并严格使用 [共享 GOAL 模板](../../references/goal-template.txt)。替换模板中的每个方括号占位符，不得遗留占位符；严格保留七个字段、顺序、全角冒号和换行，每个字段只占一个逻辑行。字段没有适用内容时写“无”，不得为了填满字段而虚构内容。同一字段有多项内容时，使用中文分号或 `(1)`、`(2)` 行内编号。

GOAL 必须自包含且不超过 4,000 个字符。不得添加标题、引言、总结或其他模板外文本，不得使用 Markdown 标题、项目符号、代码围栏或 XML/HTML 标签包装 GOAL。

描述目标状态和完成门槛，不规定非必要的内部步骤，不重复全局指令，也不把 GOAL 写成讨论记录。内容接近字符限制时，先删除重复背景和非必要实现细节，但保留结果、范围、约束与授权及可执行完成标准；不得为容纳细节而修改文件。仍无法准确表达时，只提出解除该问题所需的最小问题。

## 输出

需要澄清时，只返回一个最小问题；否则，只返回填充完成的七行 GOAL 纯文本。

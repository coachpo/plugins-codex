# Start Consensus Goal

把当前讨论整理成一个可执行 GOAL，使用 Codex Goal 机制启动并继续工作。本次调用授权创建该 Goal，并按用户已经授予的任务范围执行；不扩大沙箱、审批策略、项目指令或其他授权。

## 确立事实依据

审阅当前可见对话、压缩摘要和其他可用状态。必要时只读检查相关工作区材料，以核实项目事实、路径、命令、约束和完成检查；不得推断压缩状态未保留的细节。

分别处理决定、事实和默认值：

- 用户已接受且未被取代的决定定义目标；明确解决同一问题的较新决定取代较早决定。
- 已核实的工作区事实只用于确认可行性、路径、命令和当前状态，不扩大用户授权。
- 适用的非强制项目约定只在用户没有作出决定时作为默认值。

未被接受的助手建议、备选方案、引用、示例、头脑风暴、沉默和已被取代的决定都不算共识。不得静默拼接不兼容要求，也不得虚构需求、事实、路径、命令、接口、约束、权限、风险或阻塞项。

## 处理不确定性

当假设不会实质改变结果、范围、授权、成本或风险时，可以作出合理假设，并在“约束与授权”字段中以“假设：”明确标记。

若一个未决选择会实质改变上述任一项，只提出解决该选择所需的最小问题，不创建 Goal。不得因普通实现层面的不确定性而暂停。

## 编写 GOAL

使用简体中文编写完整 GOAL。文件路径、标识符、命令、代码、API 名称、产品名称和引用原文保留准确拼写。

编写前完整读取并严格使用 [共享 GOAL 模板](../../references/goal-template.txt)。替换模板中的每个方括号占位符，不得遗留占位符；严格保留七个字段、顺序、全角冒号和换行，每个字段只占一个逻辑行。字段没有适用内容时写“无”，不得为了填满字段而虚构内容。同一字段有多项内容时，使用中文分号或 `(1)`、`(2)` 行内编号。

GOAL 必须自包含且不超过 4,000 个字符。不得添加标题、引言、总结或其他模板外文本，不得使用 Markdown 标题、项目符号、代码围栏或 XML/HTML 标签包装 GOAL。

描述目标状态和完成门槛，不规定非必要的内部步骤，不重复全局指令，也不把 GOAL 写成讨论记录。内容接近字符限制时，先删除重复背景和非必要实现细节，但保留结果、必要证据、范围、约束与授权、完成标准、阻塞条件和交付要求；可以引用已经存在且已核实的材料，但不得仅为容纳 GOAL 而新建或修改文件。

## 启动持久 Goal

先使用 `get_goal` 检查当前状态：

- 没有未完成 Goal 时，使用 `create_goal` 创建 Goal，把填充完成的七行纯文本原样作为 `objective`。只有用户明确请求 token budget 时才传 `token_budget`。
- 现有未完成 Goal 已覆盖本次目标时，继续该 Goal，不重复创建。
- 现有未完成 Goal 未覆盖本次目标，或与本次目标在范围、授权或产物上不兼容时，说明准确冲突并只请求一个必要决定。不得声称可以编辑或清除现有 Goal，也不得为了替换它而将其标记为完成或阻塞。

若 Goal 机制不可用或创建失败，返回填充完成的目标文本和实际错误，明确说明持久 Goal 尚未启动；不得生成未经当前 Codex 能力核实的替代命令。

创建成功后发送一次简短进度更新，只报告 Goal 已启动、归并的关键决定、重要假设以及因冲突或未决未纳入的事项；随后立即继续执行。

## 执行、停止与交付

进展声明必须有当前对话或工具结果支持，尚未验证的内容明确标记。结束一轮前检查是否仍有 Goal 范围内、已获授权且当前可以完成的工作；有则继续。

完成标准全部验证且没有剩余必需工作时，使用 `update_goal` 将状态标记为 `complete`。只有 `update_goal` 的当前工具约束所规定的阻塞条件已经满足且无法继续取得实质进展时，才将状态标记为 `blocked`。不得因困难、耗时、预算将尽或暂时未完成而标记完成或阻塞；预算 Goal 完成后报告 Goal 工具返回的最终 token 使用量。

最终答复以结果开头，报告实际验证及结果。若仍受阻，报告准确阻塞项、已经尝试的内容和最小下一步。

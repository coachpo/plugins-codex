# init-deep

为目标仓库建立耐久、简洁、可验证的 `AGENTS.md` 指导层级。仓库根目录的 `AGENTS.md` 是主要产物；只有子树存在不同操作要求时才保留或创建更近的文件。

完成结果应满足：

- 后续编码代理能找到重要入口、正确的改动位置、项目特有约束和权威验证命令。
- 根文件承担仓库共同指导，子文件只写局部增量，不复述父级内容。
- 每条写入内容都有仓库证据和明确适用范围；无法确认的内容被标记为不确定或省略。
- 所有变更文件、继承关系和相关验证都已检查，报告只声称实际执行过的结果。

## 授权与停止条件

先从当前上下文和只读检查确定目标仓库、实际仓库根目录及可写范围。初始化、修复或刷新请求授权范围内的本地读取、编辑和非破坏性验证，无须逐步询问。

外部写入、删除或覆盖难以恢复的内容、明显昂贵的操作及实质性范围扩大需要确认。只有缺失决定会实质改变范围、风险或产物时才提问。

若根 `AGENTS.md` 不在可写范围内，不以只创建子文件替代；报告缺少的最小权限并停止写入。关键证据不可读取、仓库边界无法确定或必要验证无法安全运行时，报告准确阻碍和最小下一步。

## 查明有效指导与仓库边界

在多仓库工作区、子模块或嵌套版本库中，以检测到的实际项目根为准，不把工作区目录默认视为仓库根。

读取约束目标根目录及候选子树的有效 `AGENTS.override.md`、`AGENTS.md` 和配置声明的回退文件名。沿每个候选子树检查实际继承顺序：

- 同一目录采用优先级最高的非空指导文件。
- 从项目根到工作目录按路径顺序合并，越近的指导优先。
- 空文件不生效，合并内容受项目文档字节上限约束。

保留有意且仍然准确的现有规则。遇到覆盖文件遮蔽、父子冲突、仍生效的回退文件或来源不明的规则时，先确认实际影响再编辑。

## 建立证据

写入前，为每条拟写规则确认至少一个仓库证据来源及适用范围。查明有证据可得的职责与入口、改动归属、构建与开发及验证命令、生成或供应商边界，以及本地安全、兼容性、所有权或高风险约束。

优先用可用的结构化代码工具查找符号、调用关系、模块边界和入口；用文件搜索查配置、清单、任务运行器、CI、文档和字面规则。通过清单、脚本定义、测试配置和 CI 用法交叉核对命令，不凭目录名或生态惯例推断。

关键来源冲突时交叉核验。搜索结果为空、残缺或异常狭窄时，用一个有意义的替代来源或工具复查；仍无法确认的内容省略或标明不确定性。证据记录无需写入仓库。

## 决定指导层级

先确定根文件的仓库共同规则，再评估候选子树。只有以下条件同时成立时，才为子树创建或保留嵌套 `AGENTS.md`：

- 已验证的本地命令、约束、责任边界或风险确实不同于共同规则；
- 写入根文件会误导其他区域或增加明显噪声；
- 子文件只写局部增量仍有独立价值。

名称即可说明的事实、父级重复、短期目录清单和未经验证的猜测不构成子文件理由。现有子文件已无局部价值时，将其列为需确认的合并或移除项；未经确认不删除。

## 撰写

先更新根 `AGENTS.md`，确认它能独立承载仓库共同指导，再处理子文件。对现有文件做聚焦修改，保留仍然有效的规则和用户措辞。

项目已有 `README.md`、`STATUS.md`、`CONTRIBUTING.md` 或 `docs/` 权威文档时，把它们作为产品、状态、架构和项目技术规则的事实来源。`AGENTS.md` 保留代理实际需要的操作要求、局部差异和必要链接，不复制大段项目文档；代理专属行为仍以 `AGENTS.md` 为权威。

识别生成或托管区块并原样保留，不手工重写其他技能或脚本拥有的内容。`write-project-docs` 管理的根 `AGENTS.md` 文档导航区块只能由其配套脚本更新。

只写有证据、能改变代理行为的内容，例如职责与入口、改动归属、项目特有的必须或禁止事项、来源明确的验证命令及不直观的生成边界和高风险区域。根文件写共同规则，子文件只写更窄的补充或替代命令。

省略空类别、通用软件建议、名称即可知道的事实、时间戳、提交标识、易过期的完整目录盘点和未经证实的命令。重要不确定性明确写成待确认条件。

## 验证与交付

写入后重新读取每个变更文件，并检查：根文件存在且是主要产物；路径、入口和命令与证据一致；从根到子树没有冲突、失效覆盖或重复；托管区块未被越界修改；每个子文件仍满足局部价值条件；关键指导不会因合并大小限制被截断。

运行与改动最相关、成本最低的非破坏性检查。优先验证文档实际提到的命令或定义；完整测试明显昂贵时，运行能证明命令可解析、配置可加载或目标可枚举的较小检查，并说明未运行部分。不得把未执行的检查写成成功。

除需确认的移除项外，发现证据矛盾、重复或无效内容时继续修正并复验。只有根产物存在、层级决策有证据、全部变更文件已复查且相关检查已完成或明确受阻后结束。

报告以结果开头，列出创建和更新的 `AGENTS.md` 路径、关键证据来源、实际验证及结果、有意义的省略与未验证事项、需确认的移除项和最小下一步。先保留结果、证据和重要限制，再删减过程与重复内容。

彼此独立且规模较大的调查可以并行；层级决策、内容合成和最终验证由同一执行者统一完成。
